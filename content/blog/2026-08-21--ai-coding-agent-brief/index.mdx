过去一年，AI Coding Agent 的关注点经历了明显变化：从“模型能不能写代码”，逐渐转向“如何让 Agent 在真实工程环境中稳定完成复杂任务”。

本周几个重要变化进一步验证了这个趋势：Coding Agent 正在从单次对话工具，演变为包含任务管理、上下文管理、工具调用、状态恢复和多 Agent 协作的软件工程系统。

## 本周整体判断

当前 Agent 工程的核心问题已经不是生成代码质量，而是执行可靠性。

一个真实的软件开发任务通常包含：

- 理解需求和隐含约束
- 探索已有代码结构
- 制定修改计划
- 执行多文件变更
- 运行测试和验证
- 根据反馈继续调整

因此，一个优秀的 Coding Agent 需要解决的是完整的软件工程流程，而不是单个代码片段生成。

---

## 1. Codex CLI：从单 Agent 工具转向 Agent Session 管理

### 发生了什么

Codex CLI 开始增强多 Agent 和任务管理能力，包括 Agent 列表管理、Session 管理以及任务消息传递能力。

这类能力意味着 Agent 不再只是一次性的执行过程，而可以被视为长期存在的工作单元。

### 为什么重要

传统模式：

```
用户请求
 ↓
启动 Agent
 ↓
执行任务
 ↓
结束
```

未来模式更接近：

```
Agent Pool
 ├── Feature Agent
 ├── Review Agent
 ├── Research Agent
 └── Test Agent
```

任务调度、状态恢复和 Agent 间通信会成为新的基础能力。

### 工程影响

对于团队内部 Agent 平台设计，不应该只考虑 Prompt 模板，而需要考虑：

- Agent 生命周期
- Session 持久化
- Task ownership
- 消息传递
- 执行状态记录

多 Agent 并不是简单增加 Agent 数量，而是引入新的调度系统。

## 2. Claude Code：Sub-agent 与 Worktree 正在形成隔离执行模型

### 发生了什么

Claude Code 持续完善 sub-agent、worktree isolation 和 session 协作能力。

这些变化说明 Coding Agent 开始解决一个核心问题：多个任务如何安全并行执行。

### 为什么重要

代码修改天然具有副作用。

如果多个 Agent 同时修改同一个 workspace，会产生：

- 文件冲突
- 上下文污染
- 状态不可预测

因此 Worktree 不只是 Git 技巧，而逐渐成为 Agent 执行隔离边界。

### 工程建议

推荐根据任务类型选择：

| 场景 | 推荐方式 |
| --- | --- |
| 查询代码结构 | 普通 Agent |
| 独立功能开发 | Worktree + Agent |
| 长期职责 Agent | 独立 Session |
| Code Review | 独立 Reviewer Agent |

不要为了“多 Agent”而拆分任务，只有具有明确边界的任务才适合 delegation。

## 3. Skills 与 AGENTS.md：从 Prompt 配置进入工程资产阶段

### 发生了什么

越来越多 Coding Agent 开始依赖项目级配置：

- AGENTS.md
- Skills
- Hooks
- References

这些文件正在承担类似工程规范的角色。

### 为什么重要

过去开发者优化 Agent，主要优化 Prompt。

现在更重要的是设计 Agent 工作环境：

```
Project Rules
      ↓
Skill Routing
      ↓
Selected Knowledge
      ↓
Execution
```

### 工程建议

高质量 AGENTS.md 应该包含：

- 项目特殊约束
- 架构边界
- 构建和测试方式
- 禁止操作
- 领域规则

不要重复代码已经表达的信息。

Skill 也应该像软件组件一样维护：

- 有明确输入输出
- 有测试场景
- 控制上下文大小
- 避免无限堆积说明文字

## 4. 长任务可靠性：Goal、Loop 和恢复机制的重要性提升

### 发生了什么

越来越多 Agent 工具开始关注长时间任务：

- 自动恢复
- 状态保存
- Retry
- Resume
- Background execution

### 为什么重要

真实开发任务经常超过一次模型上下文窗口：

```
需求分析
 ↓
代码探索
 ↓
实现
 ↓
测试失败
 ↓
修复
 ↓
验证
```

如果 Agent 没有状态管理，任何中断都会导致重新开始。

### 工程影响

未来可靠 Agent 系统需要类似任务状态机：

```
queued
 ↓
running
 ↓
waiting
 ↓
retrying
 ↓
completed
```

这也是 Goal、Loop 类方案价值所在：它们解决的是执行可靠性，而不是简单重复发送 Prompt。

---

## 5. MCP 与工具生态：Agent 能力边界正在外移

### 发生了什么

Agent 与外部工具连接越来越重要：

- 文件系统
- Git
- 数据库
- 浏览器
- 企业 API

### 为什么重要

模型本身决定推理能力，而工具决定 Agent 可以影响什么。

未来 Agent 能力差异可能更多来自：

```
Model
 +
Tools
 +
Workflow
 +
Context Management
```

而不是单纯模型参数规模。

## 我的工程判断

AI Coding Agent 正在进入第二阶段。

第一阶段解决：

> AI 能不能帮助开发者写代码？

第二阶段解决：

> 如何让 Agent 成为可靠的软件工程协作者？

未来真正有价值的工程能力会集中在：

- 项目上下文设计
- Skill 体系建设
- Agent 生命周期管理
- 任务状态恢复
- 多 Agent 协作模型
- 自动验证体系

因此，与其不断寻找更强的 Prompt，不如开始设计适合 Agent 工作的软件工程流程。
