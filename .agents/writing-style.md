# Blog Writing Style

这是博客仓库的共享写作规范，适用于博客、Newsletter、技术评论、经验总结及其他中文长文。具体 Automation / Prompt 只描述栏目特有的信息源、结构、篇幅和发布时间，不重复这里的通用规则。

## 基本原则

- 保留事实、数字、时间、引用、链接、专有名词、命令、接口名、错误信息和责任主体。
- 不补造事实或来源，不把“可能”改成“已经”，不把分析判断改写成确定事实。
- 技术文本可以专业，目标是自然、准确、像中文母语技术作者，不强行口语化。
- 优先写清楚“谁做了什么、为什么重要、有什么影响”，少用抽象名词和宣传性大词。
- 直接引用默认逐字保留；若改写会改变数字归属、责任主体或结论强弱，则不改。

## 中文句法与节奏

- 语义连续、主语一致、属于同一逻辑链的短句，优先组织成完整复句，用逗号、分号或连接词衔接，不要为了制造节奏连续使用句号。
- 避免连续出现“三到五个字 + 句号”的碎片化断句。
- 不刻意使用“一句话一个自然段”的排版；只有确实需要停顿或强调时才单独成段。
- 不用 `为什么？因为……`、`答案是……`、`真正的问题是……` 这类模板化设问推动文章。
- 允许句长有变化，但不要故意写成散文化碎句，也不要让所有段落长度和节奏过于整齐。
- 中文句法优先，不照搬英文逻辑链。英文术语可以保留，但句子应按自然中文组织。

例如：

不推荐：

> 代码不是没用。测试确实在用。但它没有生产价值。

推荐：

> 这段代码并非没人使用，测试确实依赖它，但它没有独立的生产价值，因此继续保留只会增加维护面。

## AI 生成痕迹清理

### 开场套话

避免：

- 在当今……背景下
- 随着……的发展
- 众所周知
- 不可否认
- 值得注意的是
- 需要指出的是

能删就删，直接从实际问题、事实或观察开始。

### 机械结构

警惕：

- 首先、其次、最后
- 一方面……另一方面……
- 不仅……还/更……
- 不是……而是……
- X 很简单：……
- 设问自答
- 三连排比

这些结构不是禁用，但不能成为文章默认骨架。能自然推进就不用模板。

### 空泛判断和大词

少用：

- 赋能、深耕、闭环、抓手、支撑、打造
- 颠覆、重塑、引领、重新定义
- 意义重大、关键作用、未来可期、开启新篇章
- 从某种意义上说、本质上、归根结底

优先改成具体动作、对象、成本、限制和结果。没有事实或机制支撑的价值判断应降级或删除。

### 翻译腔

警惕：

- 对于……来说
- 基于……
- 围绕……展开
- 进行……工作
- 在……层面上
- 使得……得以……
- 这是一个……的过程
- 其、该、此、予以、借由

优先缩短主语、换成直接动词、拆掉过长定语链，让句子先表达“谁做了什么”。

### 无源权威

警惕：

- 专家认为
- 研究表明
- 数据显示
- 行业普遍认为
- 有观点指出

有明确来源就引用，没有来源就去掉权威铺垫，只保留能够成立的判断，不能补造来源。

### 收尾腔

避免用下面这些句子强行总结或拔高：

- 综上所述
- 由此可见
- 这也提醒我们……
- 真正重要的是……
- 最终答案已经很清楚了
- 这代表着行业未来的发展方向

结尾回应文章实际问题即可，也可以停在最后一个有价值的事实或判断上。

### 排版模板感

避免：

- 连环冒号
- 每一项都是“粗体标题 + 冒号”
- 过多破折号
- 每段长度近似
- 每段都采用相同起承转合
- 为了显得完整而强行列三点、五点、七点

列表只在它确实比自然段更容易阅读时使用。

### 过度表演的人情味

避免：

- 好问题
- 你提到了核心
- 我完全理解你的感受
- 你并不是……你只是……

博客正文直接进入观点、事实和论证，不需要额外姿态层。

## 技术文章

- 先讲具体问题，再抽象出方法，不从宏大背景起笔。
- 事实、分析和推断分开表达；技术判断要能指出依据。
- 能使用真实案例时，不用虚构故事替代。
- 专业术语可以保留英文，但不要为了显得专业而堆叠术语。
- 测试结果、版本、日期、数字和官方行为必须可验证；不确定时明确写出不确定性。
- 不为了“完整”重复同一观点。前文已经讲清楚的结论，后文直接引用或继续推导。
- 标题可以有传播性，但正文不要跟着标题党化。

## 改写动作

需要清理 AI 痕迹时，优先做这些动作：

- 删除整句空话和提示牌；
- 合并语义连续的短句；
- 合并弱句，减少碎片化自然段；
- 把抽象名词改回直接动词；
- 补足模糊主语和责任主体；
- 把宣传性判断落回事实和可观察结果；
- 保留必要重复，不为躲重复机械换同义词；
- 打散过于整齐的排比、列表和段落节奏。

## 发布前检查

交付或发布文章前至少检查一遍：

- 是否改动了事实、数字、引用、责任主体或判断强弱；
- 是否仍有连续短句、碎片化断句或一句一段；
- 是否还有明显的 `为什么？因为……`、`不是……而是……`、`首先/其次/最后`；
- 是否残留“值得注意的是”“综上所述”等提示牌；
- 是否存在无来源的“研究表明”“行业认为”；
- 开头是否仍在铺垫，结尾是否仍在喊口号或强行升华；
- 是否为了结构整齐而堆列表、排比和粗体；
- 是否把专业文本改得过度口语化；
- 是否有英文术语正确但中文句法生硬的句子；
- 整篇读起来是否像一个具体的中文技术作者在说明问题，而不是模型在组织答案。
